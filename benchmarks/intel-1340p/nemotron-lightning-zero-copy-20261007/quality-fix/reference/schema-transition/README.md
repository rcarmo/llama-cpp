# Rejected answer-schema transition experiment

Candidate C attempted JSON-schema constraints only after a 512-token reasoning phase, keeping 1,024 tokens for answer. Five original/held-out fact tasks, CPU and handoff (10 runs), with unchanged prompts/oracles and no result substitution. All ten failed natively before producing a turn: ordinary schema grammar rejected the reasoning end token `</think>`; lazy grammar rejected the end token or first answer `{` with an empty grammar stack. CPU C2 retries on policy/conflicts/incident reproduced the transition failure. No answer scores can be assigned from empty outputs. Full response/log/manifest files retained beside this note.

Root cause: the current shared sampler has a grammar-lazy switch but no tested stage transition tying schema activation exactly to reasoning completion. Combining `grammar_lazy` and `reasoning_budget` is not sufficient; the lazy grammar enters an invalid state after the reasoning end / answer trigger. The attempted harness changes were reverted; committed source remains at the prior verified reasoning-budget implementation. Do not retry token/pattern variations as if a schema gate exists. A correct next implementation needs an explicit two-stage sampler or separate answer-generation stage with grammar initialized at the final-answer prefix, then sampler state/acceptance tested on synthetic token streams and the existing reasoning-budget suite before any model run. It must handle natural and forced end, empty/partial JSON, EOG, tool/non-schema requests, rollback/cancellation, and answer truncation. Only then screen original/held-outs. Until then, schema-constrained answers remain blocked.

No service deployed, no source commit made, no prompt facts inserted into the grammar. GPU workload drained after the 10 failed attempts.
